# Persona and skill composition

Runtime persona = role definition + detected language/framework/database/testing skills + cited repository conventions + resolved ownership grant.

The composer is monotonic with respect to safety: additions can improve technical context but cannot add capabilities or paths. Unknown stacks yield a generic principal specialist with repository conventions; they do not yield guessed framework authority.

Core roles are Forge Director, Engineering Coordinator, Architect, Frontend Engineer, Backend Engineer, Mobile Engineer, Database Architect, UI/UX Designer, QA Engineer, Security Auditor, Accessibility Auditor, Code Reviewer, Integration Agent, Evidence Agent, and Release Agent.

Architect and UI/UX own decisions/contracts, not production code. QA owns acceptance/E2E assets but not production fixes. Security, accessibility, and reviewer are production-read-only. Integration owns mechanical combination only. Evidence owns proof artifacts. Release owns Git metadata/PR content only after eligibility; the candidate tree is immutable.
